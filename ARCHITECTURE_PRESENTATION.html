Executive Summary
Overview of the Solution

What is This Application?

A production-ready, enterprise-grade chat application built on Azure OpenAI services, providing an intelligent conversational interface with advanced capabilities.

Key Capabilities

  • Real-time Chat - Conversations powered by GPT-3.5-turbo, GPT-4, and GPT-4o
  • Retrieval-Augmented Generation (RAG) - Chat with your own data
  • Persistent Chat History - User conversation tracking via Azure CosmosDB
  • Function Calling - Integration with Azure Functions for extended capabilities
  • Multi-Datasource Support - Azure AI Search, CosmosDB, Elasticsearch, Pinecone, MongoDB
  • Enterprise Security - Azure Entra ID authentication, Microsoft Defender integration
  • Scalable Architecture - Async processing, streaming responses, containerization

Conversation Flow
Response Processing

Streaming Response Flow

Stream Mode (Default)

  • stream_chat_request()
  • async for chunk in response
  • format_as_ndjson()
  • Yield NDJSON lines
  • Frontend parses progressively
  • Lower latency, better UX

Non-Stream Mode

  • complete_chat_request()
  • Await full response
  • format_non_streaming_response()
  • Return complete JSON
  • Display all at once
  • Simpler implementation
Frontend Updates UI → Extract Citations → Render Markdown → Display to User

Function Calling
Extending AI Capabilities with Azure Functions

How Function Calling Works

1. User: "What's the weather in Seattle?"
↓
2. Azure OpenAI Response includes tool_calls
↓
3. process_function_call() → Extract function name & args
↓
4. Call Azure Function via HTTP POST
↓
5. Function Executes → Returns Result
↓
6. Add Result to Messages → Send Follow-up to OpenAI
↓
7. Final Answer Displayed to User

Best Practices & Recommendations

Security Best Practices

  • ✓ Always enable Azure Entra ID authentication in production
  • ✓ Store all secrets in Azure Key Vault, not environment variables
  • ✓ Enable Microsoft Defender for Cloud for threat protection
  • ✓ Use Managed Identity for Azure service authentication
  • ✓ Implement network security with Private Endpoints
  • ✓ Enable CORS only for trusted domains

Performance Best Practices

  • ✓ Use streaming mode for better user experience
  • ✓ Configure appropriate Gunicorn workers (CPU cores × 2 + 1)
  • ✓ Enable CosmosDB indexing for fast queries
  • ✓ Use Azure CDN for static assets in production
  • ✓ Implement request throttling to prevent abuse

Cost Optimization

  • ✓ Use GPT-3.5-turbo for non-critical conversations
  • ✓ Implement conversation TTL in CosmosDB
  • ✓ Monitor token usage with Application Insights
  • ✓ Scale App Service based on actual usage

Easy Customization Points

1. Custom Data Sources

Add new datasource by implementing:

class _CustomDataSourceSettings(BaseSettings): endpoint: str api_key: str def construct_payload_configuration(self): return { "type": "custom_source", "parameters": {...} }

2. Custom Azure Functions

Extend AI capabilities with custom functions:

  • Create Azure Function with HTTP trigger
  • Define function schema in OpenAI request
  • Handle function call in process_function_call()

Brand the interface with environment variables:

4. Custom Middleware

Add request/response processing in app.py:

  • @app.before_request for pre-processing
  • @app.after_request for post-processing
  • Custom logging, analytics, rate limiting
Troubleshooting Guide
Common Issues and Solutions
Issue Possible Cause Solution
401 Unauthorized Authentication not configured Set AUTH_ENABLED=false for dev, or configure Entra ID
Azure OpenAI 404 Wrong endpoint or model name Verify AZURE_OPENAI_ENDPOINT and MODEL settings
CosmosDB connection failed Invalid credentials or endpoint Check AZURE_COSMOSDB_ACCOUNT and key/connection string
Streaming not working API version incompatible Use AZURE_OPENAI_API_VERSION=2024-02-15-preview or later
Chat history not saving CosmosDB not enabled Provision CosmosDB and set connection strings
Frontend not loading Build not executed Run: cd frontend && npm run build
Slow response times Insufficient workers Increase Gunicorn workers in gunicorn.conf.py
CORS errors Frontend domain not allowed Configure CORS in app.py @app.after_request
